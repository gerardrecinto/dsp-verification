How it works

Same shape as a chip verification environment, at a size you can read in one sitting.

Directed tests

Reset, impulse response, every coefficient slot, saturation corners, boundary values, reset mid-stream, coefficient writes while streaming.

Constrained random

Phases switch between small, edge and full-range values. Valid gaps, coefficient writes and resets are mixed in. Every seed is replayable.

Assertions and coverage

No unknown values on outputs, saturation flag matches the data, latency fixed at two clocks. 21 coverage bins including crosses and exact boundaries.

Does the testbench catch real mistakes?

Each row is one planted bug, compiled into the design with a macro. A bug that passes every test would mean the testbench has a hole. The first full run found one: BUG_SATNEG survived because no test produced an output of exactly -32768. The boundary test was added and it is now caught.

What this is, and what it is not

Is

A working verification flow: model, scoreboard, constrained random, coverage, mutation testing, a nightly Kubernetes job, alert rules with tests, and a dashboard.

Is not

A UVM or SystemVerilog environment, formal proof, or a full DSP. The block is small on purpose and the simulator is open-source Icarus.
